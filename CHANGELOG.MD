# Changelog

## v1.2.0

Отложенные сообщения, повторы с паузой и парковочная очередь вместо бесконечного requeue,
безопасная остановка консьюмера, экранированный URI и маска пароля. Публичные типы и сигнатуры
не изменились - код сервисов компилируется без правок; новых переменных окружения нет.

### Добавлено
- `Publisher.PublishDelayed`, `PublishDelayedWithMetaData`, `PublishBatchDelayed`,
  `PublishBatchDelayedWithMetaData` и их `...Ctx`-варианты: сообщение приходит в exchange
  публикатора с исходным routing key не раньше чем через задержку. Схема: fanout-exchange и
  durable-очередь `<exchange>.delay.<задержка>` (`x-message-ttl`, `x-dead-letter-exchange` = exchange
  публикатора), объявляются лениво, один раз. Задержка - от `MinPublishDelay` (1 с) до
  `MaxPublishDelay` (24 ч), доли секунды округляются вверх; каждая уникальная задержка - своя очередь.
- `Publisher.PublishCtx`, `PublishWithMetaDataCtx`, `PublishBatchCtx`, `PublishBatchWithMetaDataCtx`:
  отправка и ожидание подтверждения брокера ограничены `ctx`.
- `Consumer.Close(ctx)`: прекратить приём, дождаться текущих обработчиков в пределах `ctx`,
  закрыть подписчиков.
- `rabbitmq.ActionRetry` - политика по умолчанию для ошибки и паники обработчика (см. ниже);
  константы `AttemptHeader`, `LastErrorHeader`, `OriginalQueueHeader`, `ParkingQueueSuffix`.
- Сквозной CorrelationID: методы `...Ctx` (в том числе отложенные) ставят метаданные `correlation_id`
  (`CorrelationIDMetadataKey`) из `sdkctx.CorrelationID(ctx)` (gosdk-core), если вызывающий не задал свои; методы без
  `ctx` id не ставят. Обработчик получает `ctx` с id из `correlation_id` сообщения (нет — новый id); повтор и `.dlq`
  несут тот же id. Требуется gosdk-core v1.3.0.

### Исправлено
- Пароль со спецсимволами (`% # / @ : ?`) ломал разбор URI: `RabbitConfig.AmqpURI` собирает URI
  через `url.URL` (логин и пароль экранированы, IPv6-хост в скобках, vhost одним сегментом).
- Текст ошибки подключения (`NewAmqpConnection`, `RabbitKernel.Init`) содержал пароль - теперь маска.
- `Consumer.handlers` - под мьютексом.

### ⚠️ Изменения поведения
- **Ошибка или паника обработчика** (по умолчанию) - больше не Nack с бесконечным requeue без паузы.
  Копия сообщения (тело и метаданные, persistent, с подтверждением брокера) уходит в
  `<queue>.retry.<пауза>` и через паузу возвращается только в свою очередь; паузы 5 с, 30 с, 2 мин,
  10 мин, 30 мин, счётчик - заголовок `x-sdk-attempt`; исходное сообщение - Ack. После 5 повторов -
  в `<queue>.dlq` (SDK объявляет её, durable) с заголовками `x-sdk-attempt`, `x-sdk-original-queue`,
  `x-sdk-last-error`, затем Ack. Если копия не опубликовалась - Nack (сообщение не теряется).
  В брокере появляются очереди `<queue>.retry.5s` ... `<queue>.retry.30m` и `<queue>.dlq`.
- Очередь со своим `x-dead-letter-exchange` в `amqp.QueueConfig.Arguments`: своя политика DLX сервиса
  не трогается. Повторов, копий и очередей SDK (`<queue>.retry.*`, `.dlq`) нет - ошибка или паника
  обработчика дают обычный Nack исходного, как до v1.2.0. Куда оно уйдёт, решает `NoRequeueOnNack`
  из конфига сервиса: `true` - брокер уводит его в DLX с заголовком `x-death` (счётчик кругов цел),
  `false` - возврат в очередь. SDK этот флаг не меняет. Свой marshaler сервиса не заменяется: обёртка
  `DeathTolerantMarshaler` ставится только вместо `amqp.DefaultMarshaler`.
  При `NoRequeueOnNack: true` у сервиса остановка консьюмера тоже отдаёт полученные, но не начатые
  сообщения в DLX (Nack watermill) - это поведение политики сервиса.
- Явно заданные `WithErrorAction` / `WithPanicAction` (`ActionAck`, `ActionNack`) работают как раньше:
  `ActionNack` - возврат в очередь (requeue), если сервис сам не включил `NoRequeueOnNack`.
- Копии в `<queue>.retry.*` и `<queue>.dlq` собираются из `msg.Metadata`: нестроковые
  заголовки исходного сообщения (числа, таблицы, `x-death`) в копию не попадают.
- Доставка at-least-once: при сбое между подтверждением копии брокером и Ack исходного (обрыв
  соединения, остановка по таймауту) сообщение придёт ещё раз - обработчик должен быть идемпотентным.
- `amqp.DefaultMarshaler` в конфиге подписчика заменяется на `marshaler.DeathTolerantMarshaler`
  с теми же настройками; помощники `NewConsumer*Config` / `NewConsumerByConfigs` ставят
  `DeathTolerantMarshaler`. Сообщения с `x-death` (после DLX) больше не падают на разборе.
  В `msg.Metadata` нестроковые заголовки отбрасываются, счётчик `x-death` - в `x-death-count`.
- **Остановка**: ctx обработчика больше не отменяется при `Stop` - начатая обработка дорабатывает.
  `RabbitKernel.Stop` прекращает приём, ждёт текущие обработчики в пределах ctx остановки, затем
  закрывает подписчиков, publisher-ы и соединение (раньше соединение закрывалось сразу и сообщение
  в обработке возвращалось в очередь - повторная обработка).
- **Падение консюмера**: если `Consume` завершился сам (ошибка подписки, закрытый канал или
  соединение), kernel пишет ERROR и останавливает приложение через `App.Fail` (раньше сервис
  оставался запущенным без приёма сообщений). `Consume` возвращает ошибку, если канал сообщений
  закрылся без остановки.
- **Sentry**: payload сообщения по умолчанию не отправляется (раньше - до 2 КБ), metadata
  (заголовки) - никогда. Отправляются handler, panic, id и размер сообщения, очередь, exchange,
  ключ привязки, номер повтора. `WithSentryPayloadLimit(n)` с `n > 0` - явное включение payload
  (первые `n` байт); `0` теперь означает «не отправлять» (раньше - без лимита).
- `fmt` (`%v`, `%+v`, `%s`, `%#v`) и `json.Marshal` конфига `RabbitConfig` выводят `***` вместо пароля;
  поле `Pass` - по-прежнему `string` с настоящим значением.
- `RABBITMQ_VHOST` без ведущего `/` (`main`) раньше давал неразбираемый URI, теперь - vhost `main`.
  `/`, пусто, `/main`, `/%2F` - смысл прежний.
- Логгер watermill у publisher-а - по уровню логгера SDK (раньше debug и trace всегда).

## v1.1.1

Зависимость `gosdk-core` поднята до v1.2.0. API пакета не изменился.

## v1.1.0

Переход на `gosdk-core` v1.1.0. API пакета не изменился.

### Изменено
- `gosdk-core` v1.0.29 → v1.1.0.

### ⚠️ Изменения поведения
- Требует `gosdk-core` v1.1.0. Поднимать вместе с `gosdk-http-core` ≥ v1.2.0, иначе сервис
  теряет AppInfo (имя сервиса) в логах запросов и в Sentry.
- Логгер `gosdk-core` экранирует управляющие символы: одна запись лога - одна строка;
  `logger.Dump` пишет значение одной строкой.

## v1.0.13

Минимальная версия Go поднята до 1.27.3. API и поведение пакета не изменились.

### Изменено
- `go.mod`: `go 1.26.0` → `go 1.27.3`. Причина - уязвимости стандартной библиотеки go1.26.0
  (`govulncheck`), исправлены в новых версиях Go. На go1.27.3 `govulncheck` уязвимостей стандартной библиотеки не находит.
- `gosdk-core` поднят до v1.0.29 (переход на Go 1.27.3, API не изменился).

### ⚠️ Изменения поведения
- Потребителю нужен Go ≥ 1.27.3: после `go get` этой версии в его `go.mod` станет `go 1.27.3`.
  С `GOTOOLCHAIN=auto` toolchain скачается сам; с `GOTOOLCHAIN=local` на Go < 1.27.3 или в образе
  без доступа к `proxy.golang.org` сборка упадёт - образ сборки `golang:1.27.3`.

## v1.0.12

`RABBITMQ_*` из переменных окружения процесса (Docker, k8s, `docker run -e`) читаются
и без `.env`. Типы, поля и сигнатуры не изменились.

### Изменено
- `gosdk-core` поднят до v1.0.28: `logger.Error` пишет на уровне Error.

### Исправлено
- У полей `config.RabbitConfig` есть `json`-теги с теми же именами, что `mapstructure`
  (`json:"RABBITMQ_HOST"` и т. д.). Без них `InitConfig` из `gosdk-core` находил переменную
  в окружении, но не мог положить её в поле: применялись только ключи, которые есть в `.env`.
  Требуется `gosdk-core` v1.0.27+ (в `go.mod` - v1.0.28).

### ⚠️ Изменения поведения
- Сообщения `logger.Error` видны на уровнях info и выше с `[ERROR]` (раньше писались
  на уровне Debug и на рабочих уровнях не выводились): `app.RabbitKernel` - «rabbit consumer stopped»,
  consumer `rabbitmq` - «failed to register amqp handler», «failed to subscribe to queue».
- Переменная `RABBITMQ_*`, которой нет в `.env`, но которая задана в окружении процесса,
  теперь применяется (раньше молча игнорировалась, поле оставалось пустым). Если `.env` нет совсем,
  конфиг целиком берётся из окружения. Для ключей, которые есть в `.env`, окружение было главнее
  и раньше.
- Пустая переменная в окружении (`RABBITMQ_PASSWORD=`) теперь перекрывает значение из `.env`
  пустой строкой (раньше бралось значение из `.env`). Не задавайте пустые `RABBITMQ_*`
  в окружении, если значение должно прийти из `.env`.
- `json.Marshal(RabbitConfig)` выдаёт ключи `RABBITMQ_*` вместо имён полей (`Host`, `Pass`…).
  В SDK, `go-sdk-rest-template` и `gosdk-rabbitmq-consumer-template` конфиг в JSON не сериализуется.
- Затронуты все места, где конфиг читается через `InitRabbitConfig`: `app.RabbitKernel`
  (`Init`) и сервисы, которые подключают этот kernel.
